IinPublic — Gun.js Database Architecture

A public self-definition platform, NOT a chat app. Identity = Q&A list + 4 talk types + SEA-encrypted interactions.

The Three Pillars

Pillar 1 — Profile Q&A

Each user builds a QuestionAnswer[]. Auto-generated or manual. Visibility: public | contacts_only | private.

Pillar 2 — Talks (4 Types)

Structured interaction templates broadcast via Gun mesh:

  • tag — single keyword toggle
  • flow — linear Q/A chain (path graph)
  • survey — independent polls (star graph)
  • route — branching DAG w/ FNV-1a hash

Pillar 3 — Interactions

Conversations triggered by talk matches. Two-writer message DAG with SEA+ECDH encryption. Every interaction cryptographically signed in append-only ledger.

Gun Graph Structure

All data lives in Gun.js graph paths. Two users (A and B) share a mesh; their personal data flows through the same topology.

Layer 1 — SEA Identity & Crypto
gun.sea()Generates two keypairs: pub/priv (signing) + epub/epriv (ECDH)Private, never transmitted raw
localStorage custodyAES-GCM ciphertext wrapped by PBKDF2-SHA256 (150k iterations)Device-only, exportable via signed recovery package
Layer 2 — User Records (Public Mesh)
users/<userId>stageName, headshot, pub/epub keys, location{region}, languages[], createdAtPublic mesh — everyone can read
private/profileFull QuestionAnswer[] (incl private), knownPeople[], blockedUserIds[], talkFilters[]SEA-encrypted — only owner decrypts
user-public-profile/<userId>headshot, profileJSON (visibility applied), languagesJson, interestsJsonPeer-discovery optimized subset
user-tags/<userId>{tags: Record<tagName, weight>, updated} — categories: for-sale, housing, community...Public (discovery)
tag-index/<tagName>/<userId>Reverse index mapping tag → set of users who have itPublic (discovery)
user-talk-filters/<userId>TalkIntakeFilters: min/maxDistance, allowedLanguages, blockDirtyWords, requiredGrammarPublic (incoming filter)
Layer 3 — Talk Definitions & Chatrooms
talks/<talkId>Stringified Talk: {id, title, authorId, type, questions[], isAdult, language, tags[], usageCount, expiresAt?}Public mesh — all nodes see
Talk type topology: tag — isolated node (Boolean flag)  |  flow — path graph (linear Q/A)  |  survey — star graph (independent polls)  |  route — branching DAG w/ FNV-1a contextHash for O(1) lookup)
chatrooms/<id>/users/{userId}{isActive: true/false} — membership flag. Also: visitCount, uniqueVisitorsPublic mesh
bulkJobs/<jobId>Broadcast job: {talkId, senderId, targetScope, sentCount, matchedCount...}Internal tracking
Layer 4 — Incoming Index, Conversations & Messages
ownerIncomingTalkIndex/<receiverId>/<identityKey>Clustered topics: {title, senders{}, talkIds={}, questionCount, latestTalkId}. Content-hash-based identityKey = one topic per person → NOT 47 duplicatesSemi-public (owner-scoped)
conversations/<convId>participants:[A,B], talkId?, status (active|matched|ignored|expired), answers[], createdAt, matchedSemi-public
users/<id>/conversations/...}Indexed per-user — quick lookup of "my conversations + otherUserId"User-scoped index
pairConversations/{pairId}/{convId}/messages/Duplicate message storage in pair-scoped paths for direct-p2p mode. pairId = sorted(A,B).join("__").Pair-scoped, SEA-encrypted (non-public channels)
Layer 5 — Interaction Ledger
ledger/<pubkey>/events/...Signed event: {id:CIDv1 seq, prev:CIDv1, kind, pubkey, timestamp, contentJson, sig}
ledger/<userId>/headFeed head pointer: {seq, prevCid} — chain verification
ledger/<userId>/stateBroadcasted LedgerState: maps userId → highest seq for delta-sync handshake (O(Delta) sync)
ledger/{userId}/inbox/{eventId}Incoming delta events pushed by peers during sync: {eventId, deliveredAt}

Ledger Event Kinds

KindMeaning
TALK_CREATEDNew talk definition authored by user. Content: {talkId, title, type, language}
TALK_BROADCASTTalk broadcast with recipients listed. Content: {talkId, recipientCount, chatroomIds[]}
TALK_RECEIVEDTalk received from sender's delivery system. Content: {talkId, senderId}. Incoming talk filter applied per user-talk-filters/.... Cluster merge into index.
TALK_ANSWEREDAnswer submitted with outcome. Content: {talkId, responseId, outcome: match|mismatch|ignore}
TALK_SUPERSEDEDOld talk replaced by new version. Content: {oldTalkId, newTalkId}. Auto-supersedes incoming entries.
TALK_WITHDRAWNAuthor withdrew talk with grace period. Content: {talkId, gracePeriodMs}

Two-Person Interaction Flow

How Two people share their interactions from start to finish:

Step 1 — A creates + broadcasts a talk
A defines a Talk (type: tag|flow|survey|route) stored at talks/<id>. Ledger event TALK_CREATED signed via SEA. Broadcast to chatrooms + mesh delivers copies + peer discovery via tags.
Step 2 — B receives talk delivery
Gun mesh pushes to receiver's node. Cluster merged into ownerIncomingTalkIndex/B/<identityKey>. Ledger event TALK_RECEIVED recorded. Incoming talk filter (distance, language, blockByWords...) applied per user-talk-filters/B. Content-hash-based identityKey ensures one topic per person — NOT 47 duplicates.
Step 3 — B answers
B submits answers stored at conversations/<convId>/answers<qId>. Ledger event TALK_ANSWERED with outcome (match|mismatch|ignore).
Step 4 — Match occurs
When answers trigger match: conversation created at conversations/<convId>. Both participants indexed under users/A/conversations/..} and users/B/conversations/.... Ledger event MATCH_CREATED.
Step 5 — Messages exchanged
Each message persisted to Gun with idempotent writes. Stored in BOTH mesh path AND pair-private path. For non-public channels, text encrypted via SEA-ECDH: SEA.encrypt(text, SEA.secret(peerEpub, myPair)). prevSeenDAG link forms two-writer DAG for deterministic offline merge.
Step 6 — Delta-sync converges
Both peers publish ledger/{id}/state containing highest seq per user feed. Read peer's state → compute missing events pushed to ledger/peerId/inbox/<eventId>. Inbox subscription ingests remote events with SEA sig verification.

Encryption Model

SEA Signing Keys (pub/priv)

Used for: signing ledger events, talk authorship proof. Published to mesh at users/id/pub. Every event carry SEA signature verified by any reader.

SEA Ephemeral Keys (epub/epriv)

Used for: ECDH shared-secret derivation between peers. Each pair shares secret via SEA.secret(epub_A, pair_B) or vice versa.

Message Encryption

When channel is not public, text encrypted with shared secret:
SEA.encrypt(plainText, sharedSecret)
Decrypted on read with owner's epriv key. Two-writer DAG ensures deterministic offline merge without central sequencer.

Key Custody

Full keypair stored in localStorage as AES-GCM ciphertext wrapped by PBKDF2-SHA256 (150k iterations). Supports export/recovery via signed recovery package.
