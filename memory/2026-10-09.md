# 2026-10-09

- OPEN-40 Nearby map UI now derives map bounds locally from the active Nearby assignment, shades
  and focuses that cell in MapLibre, and reports its approximate diameter beside the number of
  Place pins. The map bounds stay in UI memory and never enter room presence/control metadata.
- Return to Nearby already recomputes the automatic room/certificate path and clears traveler
  state; the UI checklist is now complete. Legacy hierarchy E2E fixtures still need retirement.
- OPEN-40 Places now have an ownerless first capacity gate against release-wide `C`. Admission is
  two-phase: a serialized 15-second reservation consumes capacity but is not room presence; after
  the old room stops, the token commits active membership. Full/unverifiable reservations leave
  the current room untouched, saved full Places fall back to Nearby, and creator identity grants no
  seat priority. Embedded nodes must confirm both phases with the hub and cannot swallow its 409.
- The final decentralized Place policy remains open: reservations are currently index-memory and
  userId-authentication is not yet signed/portable, so ownerless partition reconciliation still
  requires signed evidence design and partition/reconnect tests.
- Full Places now offer an explicit Nearby-at-the-pin fallback. It routes from the deliberately
  public Place point, not the visitor's GPS; preserves and recomputes the user's real home; marks
  the remote Nearby member as a traveler; persists/re-verifies across restart; and follows Nearby
  capacity refinements without turning the remote cell into home.
- Finished the TechSupport Contacts-only migration in staged coverage: legacy support roster rows
  are filtered before count/render, the progressive room baseline is ordinary Tom + Adam (+ Eve),
  and generic Talk scenarios no longer use the TechSupport root as a room participant.
- Began the hard Gun private/control split: all `putPrivate/getPrivate` traffic now uses the
  peerless IndexedDB worker Gun, with first-read import from old SEA-ciphertext peered records and
  fail-closed behavior if the local store is unavailable. The plaintext incoming-Talk cluster
  envelope also moved local/private with decrypted subscriptions and legacy import. Pair-message
  and ledger compatibility graphs remain to migrate.
- The former expected-failure Talk hub-wire audit is now a passing release gate: a real two-user
  create/announce/receive/answer exchange captured 232 WebSocket/HTTP events with zero plaintext
  title, question, or answer markers. The related direct-delivery fixture was migrated from its
  stale Global selector and public-envelope assertion to Nearby plus local-private storage.
- Finished the next private/control split slice: pair-message bodies and their bounded checkpoint
  history now live in encrypted peerless local envelopes; signed ledger events, heads, indexes,
  and checkpoints are local too. Endpoint reconciliation uses authenticated ordered DataChannel
  digest/backfill and author-bound ledger event batches, never a Gun inbox or third-person relay.
- A real-browser pruning/catch-up run exposed the directionality requirement for active ledger
  resync. Added a signed `ledger-sync-request`: the lagging peer returns its state, then the current
  peer sends the missing delta. Full unit suite (2969 tests), typecheck, lint, and the targeted
  two-browser checkpoint/pruning/delta-sync scenario pass. Generic conversation discovery and deal
  confirmation metadata remain public control pending a direct first-message wake-up design.
