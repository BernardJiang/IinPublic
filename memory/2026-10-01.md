# 2026-10-01

- Implemented the explicit **Whenever offered** chatbot contract as a separate, versioned question-default store. Its key includes the normalized question, language, selection mode, and tag scope, but deliberately excludes the choice set and rolling conversation context.
- Resolution stays deterministic: exact rolling/root context wins first; otherwise the first user-ordered contracted answer that is present in the offered choices is reused. No fuzzy matching, subset enumeration, or inferred preferences are generated.
- Choosing a new Whenever-offered answer moves it to the front while retaining older answers as fallbacks (for example, Kiwi before Apple when both are offered, Apple when Kiwi is absent).
- Added response and review UI controls, Preferences management, migration support, English/Chinese copy, and phone-width layout handling. The broad contract is restricted to single-choice questions.
- Added unit and browser E2E coverage for reordered, two-choice, four-choice, new-preference, fallback, no-known-choice, exact-context-precedence, chained-flow, persistence/mutation, and 320px viewport cases.
- Validation: TypeScript and focused ESLint passed (one pre-existing unused-variable warning); complete unit suite passed with 260 suites / 2,592 tests; focused Chromium E2E passed 3/3.
