## Android 7 / FRD-L04 physical-device compatibility

- Fixed Android 7 verifier crash by isolating API 26 Wi-Fi Aware classes in a reflectively
  loaded provider.
- Allowed plaintext only for the embedded node's loopback-only transport; production LAN HTTP
  remains rejected.
- Worked around Chrome 101 WebView automation limitations by using Playwright's Android/Clank
  transport, selecting blank-package WebViews by PID, waiting for the actual page target, and
  giving legacy targets a stabilization interval before attachment.
- Replaced unbounded Playwright Android shell/teardown operations with bounded adb subprocesses.
- Synced runtime build `7e1f7c26` to C10, VOG-L29, and FRD-L04 without deleting app identity data.
- FRD-L04 real-device boot test passes in 32.4 seconds; C10 also passes. Targeted typecheck, lint,
  and 13 unit tests pass.
- Diagnosed FRD-L04 talk creation failure as its old WebView exhausting the 5 MB localStorage
  quota: Gun's redundant `gun/` graph cache used about 5.2 MB. Embedded native origins now remove
  only that cache and disable Gun browser persistence; identity and encrypted key-custody records
  remain intact because the embedded Node graph is authoritative for native shells.
- VOG-L29 ADB transfers hang on multi-megabyte payloads, but 128 KB uncompressed chunks reassemble
  reliably and were verified by SHA-256 before deployment. `DUM0219418001663` is its ADB serial;
  `VOG-L29` / VOGUE identifies Huawei's P30 Pro device family.
- Added deadlines to best-effort chatroom membership HTTP synchronization and matrix setup/teardown
  so a stalled device-local request reports promptly instead of consuming the 15-minute watchdog.
- The full physical seven-client matrix passes in 5.2 minutes: three Android devices (VOG-L29,
  C10, FRD-L04), macOS Electron, Chromium, WebKit, and Firefox all joined Global, authored and
  broadcast one talk, and completed the seven-node receive ring with their existing identities.
- A later visual observation caught a matrix false positive: `WebTalkService.createTalk()`
  projected a local OUT row before the authoritative Gun repository write, so a failed commit
  displayed "Failed to create talk" while the test still passed on the ghost row. Projection now
  occurs only after commit, transient idempotent commits retry three times, and unit coverage
  proves persistent failures leave no `myTalks`/`myAuthoredTalks` record.
- Added an opt-in single-device authoritative Talk commit test. FRD-L04 passes it in 43.1 seconds,
  including direct read-back of the repository record. A post-fix loaded matrix confirmed all
  seven authoritative authoring steps, then failed later when C10's WebView page closed during
  response completion; that later failure is separate from Talk creation.
- Physical diagnostics also exposed a separate Android embedded-Node limitation: signaling-relay
  requests return HTTP 400 `WebCrypto SHA-256 is not available`. Legacy delivery fallback still
  allowed authoring/broadcast, but direct P2P signaling compatibility remains follow-up work.
